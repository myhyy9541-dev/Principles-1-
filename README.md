# فرسان لان — مراسلة P2P محلية

تطبيق مراسلة عربي RTL. يعمل كل جهاز كنظير مستقل؛ يكتشف Windows وAndroid أقرانهما على Wi‑Fi محلي، ويمكن ربط هاتفين Android عبر Wi‑Fi Direct أو نقطة اتصال محلية ينشئها Android أو Bluetooth Classic بعد الاقتران. يعلن Android عن هوية التطبيق محليًا عبر Wi‑Fi Direct DNS-SD، ويتيح بدء الربط عند اختيار جهة الاتصال. لا توجد خدمة سحابية أو خادم مركزي يرحّل محتوى الرسائل أو الملفات. إصدار Windows الحالي `0.5.0` وإصدار Android الحالي `0.8.0`.

> هذا تنفيذ مستقل لأفكار المراسلة المحلية؛ لم تُنسخ شيفرة LAN Messenger المرخّصة GPL-3.0. ترخيص هذا المشروع MIT.

## طرق الاتصال

1. **Wi‑Fi:** يعلن Windows وAndroid عبر UDP `43820` على واجهات الشبكة المتاحة. يستخدم Android كذلك اكتشاف DNS-SD الأصلي في Wi‑Fi Direct لربط هوية جهة الاتصال بعنوان جهاز P2P، ثم يتفاوض النظام على مجموعة ويتصل التطبيق عبر TCP `43821`. يمكن أيضًا إنشاء مجموعة يدويًا أو طلب LocalOnlyHotspot أو استخدام شبكة Wi‑Fi قائمة. لا يوجد خادم مركزي أو Windows وسيط.
2. **Bluetooth Classic/RFCOMM:** يقترن المستخدم بالجهاز الآخر من إعدادات النظام. يبدأ Android مستمع RFCOMM بعد منح الإذن، ويستطيع الاتصال بجهاز مقترن؛ يتصل Windows عبر منفذ Bluetooth SPP/COM الصادر. لا يحتاج النقل إلى عنوان IP أو خادم وسيط.
3. **مشاركة الملفات:** ترسل الملفات على شكل أجزاء 32 كيلوبايت، ويُحفظ محتوى النقل المباشر على Android في IndexedDB بدل الاحتفاظ بالملف كاملًا في ذاكرة التطبيق. حد الملف الحالي 10 ميغابايت.
4. **الصوت والكاميرا:** مكالمات WebRTC المباشرة متاحة عبر Wi‑Fi/IP فقط. Bluetooth Classic في هذا الإصدار مخصص للرسائل والملفات، وليس ناقلًا لصوت/فيديو أو إشارة WebRTC.

## الميزات

- اكتشاف أقران Windows وAndroid تلقائيًا عبر UDP في الشبكة المحلية، واكتشاف هوية أجهزة Android عبر Wi‑Fi Direct DNS-SD.
- دردشة عامة وخاصة ومجموعات وسجل محلي وإيصالات التسليم/القراءة.
- اتصال Bluetooth Classic مباشر بين Android وWindows، وبين هاتفين Android مقترنين؛ واتصال Wi‑Fi مباشر بين هاتفين Android عبر Wi‑Fi Direct أو نقطة اتصال محلية أو شبكة محلية قائمة.
- مشاركة ملفات P2P مجزأة، مع تقدم النقل وإيقاف/استئناف/إلغاء؛ حد الملف 10 ميغابايت.
- Android يحتفظ بملفات النقل المباشر في IndexedDB وينزّلها إلى الهاتف؛ ملفات Wi‑Fi تُحمّل من النظير الذي يخزنها.
- مكالمات صوتية ومرئية WebRTC عبر Wi‑Fi مع التحكم بالميكروفون والكاميرا.
- واجهة عربية RTL متجاوبة؛ طرق الاتصال مرتبة في قائمة قابلة للطي لتبقى المحادثة ظاهرة على الهاتف. لا يعتمد Bluetooth على اتصال إنترنت.

## استخدام Bluetooth

### Android ↔ Android

1. فعّل Bluetooth على الهاتفين، واجعلهما قابلين للاكتشاف مؤقتًا عند الحاجة، ثم أجرِ الاقتران من إعدادات Android. يجب أن يكون Bluetooth Classic مدعومًا على الجهازين.
2. افتح «فرسان لان» على الهاتفين، اضغط **بلوتوث**، واسمح بإذن «الأجهزة القريبة» عند الطلب. يبدأ كل هاتف مستمع RFCOMM.
3. على أحد الهاتفين اختر الجهاز المقترن من القائمة واضغط **اتصال**. بعد ظهور حالة الاتصال، يمكن بدء محادثة مباشرة ومشاركة ملف.

### Android ↔ Windows

1. اقترن الهاتف والكمبيوتر من إعدادات Bluetooth في النظام. على Android افتح لوحة Bluetooth في فرسان لان حتى يبدأ مستمع RFCOMM.
2. في Windows، أنشئ **Outgoing COM port** لخدمة Serial Port Profile (SPP) الخاصة بالهاتف من إعدادات Bluetooth/COM Ports. تتطلب بعض إصدارات Windows تفعيل خدمة Serial Port على الهاتف أولًا.
3. في فرسان لان على Windows افتح لوحة Bluetooth، حدّث المنافذ، اختر منفذ COM الصادر واضغط **اتصال**. ابدأ أيضًا الاقتران/المستمع على Android قبل الاتصال.
4. النقل عبر Bluetooth لا يفتح تلقائيًا عند بدء التطبيق: الاقتران واختيار COM/الجهاز إجراء صريح من المستخدم. إذا انقطع الرابط، أعد الاتصال من اللوحة.

## Android ↔ Android عبر Wi‑Fi Direct

1. افتح «فرسان لان» على الهاتفين وشغّل Wi‑Fi. يسمح كل هاتف بإذن **الأجهزة القريبة** على Android 13+، أو إذن الموقع وخدمات الموقع على Android 8–12 عند طلبها. يستخدم التطبيق DNS-SD المحلي للإعلان عن هوية الجهاز والبحث عن الأقران، ولا يحتاج راوترًا أو نقطة اتصال أو Windows أو إنترنت.
2. تظهر أجهزة Android القريبة المكتشفة كجهات اتصال في قائمة المحادثات. اضغط جهة الاتصال التي تريد الاتصال بها من أحد الهاتفين؛ يبحث الجهاز عن هويتها ثم يطلب Wi‑Fi Direct إلى عنوان P2P المطابق. أبقِ التطبيق مفتوحًا على الهاتفين؛ وقد يعرض Android نافذة موافقة على تأسيس المجموعة، ويجب قبولها إذا ظهرت.
3. بعد تأسيس مجموعة P2P يقرأ التطبيق عنوان مالك المجموعة، ويفتح قناة الرسائل TCP `43821`، ثم يثبت ملف النظير عبر المصافحة. انتظر ظهور حالة الاتصال قبل إرسال الرسائل أو الملفات. مكالمات WebRTC تحتاج مسار IP مباشرًا ويجب اختبارها على الجهازين.
4. إذا كان Wi‑Fi Direct غير مدعوم أو منعه النظام/الشركة المصنّعة، يمكن استعمال QR أو عنوان IP يدويًا فوق شبكة Wi‑Fi قائمة؛ هذا البديل لا ينشئ شبكة جديدة وقد يتأثر بعزل الأجهزة.

## Android ↔ Android عبر نقطة اتصال محلية

1. في الهاتف المضيف افتح **خيارات الاتصال** واختر **نقطة اتصال محلية — دون إنترنت** ثم **إنشاء نقطة اتصال**. وافق على إذن الأجهزة القريبة في Android 13+، أو إذن الموقع المطلوب من النظام على الإصدارات الأقدم. يبدأ التطبيق `WifiManager.startLocalOnlyHotspot()` ويعرض اسم الشبكة وكلمة المرور.
2. صِل الهاتف الآخر بالشبكة الظاهرة عبر إعدادات Wi‑Fi في Android، أو امسح رمز الانضمام بكاميرا الهاتف. هذه النقطة محلية ولا توفر إنترنت؛ إذا منع النظام تشغيلها مع Wi‑Fi Direct أو نقطة أخرى، أوقف الاتصال المتعارض ثم أعد المحاولة.
3. أعد فتح فرسان لان على الهاتفين. سيبحث التطبيق عن النظير تلقائيًا؛ إذا لم يظهر، افتح خيار **شبكة Wi‑Fi قائمة** واعرض رمز فرسان لان على المضيف وامسحه بالهاتف الآخر. يمكن استخدام عنوان المضيف الظاهر في معلومات الشبكة للاتصال اليدوي عند الحاجة.
4. لإيقاف النقطة اختر **إيقاف النقطة** من اللوحة. يُغلق التطبيق حجز النظام أيضًا عند إنهائه. هذا الخيار متاح من Android 8.0 (API 26) فما فوق، لكن قدرة تشغيل Hotspot بالتزامن مع أوضاع Wi‑Fi الأخرى تعتمد على الجهاز وإصدار النظام.

## Android ↔ Windows عبر Wi‑Fi

1. وصّل الهاتف وWindows إلى شبكة Wi‑Fi محلية واحدة، مع السماح بحركة الأجهزة بينها وإيقاف عزل عملاء Wi‑Fi.
2. اسمح لـ«فرسان لان» في Windows Firewall ضمن الشبكات الخاصة. يستخدم Windows TCP `43821` للاتصالات وUDP `43820` للاكتشاف، إضافة إلى حركة UDP الخاصة بـWebRTC.
3. ثبّت APK وافتح التطبيق؛ سيبحث عن أقران Windows تلقائيًا. عند أول مكالمة سيطلب Android إذني الميكروفون و/أو الكاميرا حسب نوع المكالمة.
4. يتطلب Android 8.0 (API 26) أو أحدث. APK الاختبار `0.8.0` موقّع بمفتاح Debug للتثبيت الجانبي، وليس إصدار متجر Play. قد تحتاج إلى السماح لمتصفح الهاتف بتثبيت التطبيقات غير المعروفة.

## البناء

### Android

يعيد Gradle استخدام واجهة `src/` وSocket.IO من المشروع نفسه. يتطلب بناء APK Android SDK Platform 36 وBuild Tools 36.0.0.

```bash
npm ci
cd android
./gradlew testDebugUnitTest assembleDebug
```

يشغّل CI على **JDK 26**، أحدث إصدار Java تم اختياره لبيئة البناء، مع Gradle `9.6.0` وAndroid Gradle Plugin `9.4.0`. يستخدم كود التطبيق bytecode Java `17`؛ الهاتف لا يثبّت JDK 26، بل يشغّل التطبيق على Android Runtime (ART). يرفع سير عمل **Build Android APK** ملف `Fursan-LAN-Android-0.8.0.apk` كـartifact لمدة 30 يومًا.

### Windows

يتطلب بناء Windows Node.js `22.12` أو أحدث؛ ملف Windows النهائي لا يحتاج إلى تثبيت Node.js.

```bash
npm ci
npm test
npm run build:win
npm run build:portable
```

ينتج مثبت NSIS ونسخة portable باسمين مستقلين داخل `release/`. يُضمّن Windows دعم Bluetooth عبر منفذ SPP/COM باستخدام serialport.

## الحدود والأمان

- Bluetooth يحتاج **Bluetooth Classic/RFCOMM**، واقترانًا مسبقًا. لا يستخدم BLE، ولا ينشئ اقتران النظام نيابة عن المستخدم. يتطلب Windows منفذ COM صادرًا متوافقًا؛ توفره يختلف حسب محول Bluetooth والتعريفات.
- اكتشاف Wi‑Fi Direct التلقائي يعمل أثناء فتح التطبيق؛ يحتاج إذن Wi‑Fi القريب، وعلى Android 8–12 يحتاج إذن الموقع وتفعيل خدمات الموقع وفق متطلبات النظام. قد يعرض Android نافذة موافقة للمجموعة، ولا يستطيع التطبيق تجاوزها أو قيود Wi‑Fi Direct الخاصة بالمصنّع. QR المحلي بديل لاتصال عبر شبكة قائمة وليس تجاوزًا لعزلها. يلزم اختبار عتادي فعلي.
- مكالمات الصوت/الفيديو لا تعمل عبر Bluetooth؛ يلزم مسار IP مباشر لاستخدام WebRTC.
- الشبكات الفرعية المختلفة أو الإنترنت/VPN غير مختبرة؛ الاكتشاف يعتمد UDP broadcast. قد تمنع سياسات العزل أو جدار الحماية اتصال Wi‑Fi.
- لا توجد مصادقة تشفيرية على مستوى التطبيق أو تشفير طرفي مستقل. اقتران Bluetooth قد يوفّر حماية وصلة النظام، لكنه ليس بديلًا عن E2EE ومصادقة هوية الأقران. استخدم التطبيق على أجهزة وشبكات موثوقة فقط، ولا تتبادل معلومات شديدة الحساسية.
- اختبارات CI والوحدات لا تثبت التوافق مع كل هاتف أو محول/تعريف Windows. يلزم اختبار عتادي فعلي قبل وصف التوافق بأنه شامل. ملفات Windows غير موقعة رقميًا وAPK Debug غير مخصص للنشر التجاري.

## الاختبارات

`npm test` يشمل اختبارات مخزن الرسائل والملفات والخصوصية، وبروتوكول الإطارات، وعميل Bluetooth/Wi‑Fi، وموصل COM، ومخزن IndexedDB. يختبر `./gradlew testDebugUnitTest` ترميز الإطارات واكتشاف الأقران واختيار بادئ اتصال Wi‑Fi واحدًا وسياسة عناوين LAN. الاختبارات الآلية لا تحل محل تجربة جهازين فعليين؛ يلزم تأكيد وصول UDP broadcast وTCP بين الهاتفين على الشبكة المستخدمة، إضافة إلى اختبار Bluetooth Classic/SPP على عتاد فعلي.
