# فرسان LAN — مراسلة P2P محلية

تطبيق مراسلة عربي بواجهة RTL. كل نسخة على Windows تعمل **كنظير مستقل**: تكتشف الأجهزة القريبة وتفتح اتصالًا مباشرًا بالنظير المستهدف. لا توجد غرفة مركزية ولا خادم وسيط لتوجيه محتوى الرسائل أو الملفات. إصدار التطبيق `0.4.0`.

> هذا تنفيذ مستقل لأفكار المراسلة المحلية؛ لم تُنسخ شيفرة LAN Messenger المرخّصة GPL-3.0. ترخيص هذا المشروع MIT.

## طريقة الاتصال

1. عند التشغيل، يفتح كل جهاز نقطة نهاية شبكية محلية على TCP `43821` ويعلن وجوده عبر UDP broadcast على `43820`.
2. تتصل الواجهة مباشرةً بكل نظير مكتشف، وتستخدم هذه الوصلات لإرسال الرسائل أو أجزاء الملفات مباشرةً إلى الأجهزة المستهدفة.
3. نقطة نهاية الجهاز المستقبل تحفظ نسخة محلية وتسلمها إلى واجهة ذلك الجهاز فقط؛ **لا تعيد تمرير الرسائل أو الملفات التي استقبلتها إلى نظير ثالث**.
4. الصوت والكاميرا يستخدمان WebRTC مع وسائط مباشرة بين الأقران. إشارات بدء/تفاوض المكالمة تصل عبر اتصال النظير المعني فقط.

وجود مستمع محلي على كل جهاز جزء من عمل النظير نفسه، وليس خادمًا مركزيًا. في المحادثة العامة تُرسل نسخة من الرسالة مباشرةً إلى كل نظير متصل. في الخاص والمجموعات يُرسل المحتوى مباشرةً للأعضاء المستهدفين.

## الميزات

- اكتشاف أقران تلقائي داخل الشبكة المحلية عبر UDP broadcast.
- دردشة عامة وخاصة ومجموعات، مع سجل محلي لكل جهاز وإيصالات تسليم/قراءة.
- رسائل خاصة مؤجلة محفوظة على جهاز المرسل عند عدم اتصال النظير، وتُسلّم عند عودة اتصال مباشر بين الجهازين.
- مشاركة ملفات ومجلدات مباشرةً من النظير المرسل إلى الأجهزة المستهدفة، بنقل مجزّأ وتقدم وإيقاف واستئناف وإلغاء؛ حد الملف 10 ميغابايت.
- يحتفظ كل جهاز بنسخته المحلية من الملفات التي أرسلها أو استقبلها؛ لا تُحمّل الملفات إلى وسيط.
- بحث في سجل الجهاز وتصديره إلى CSV، ومعاينة للصور.
- مكالمات صوتية ومرئية WebRTC بين الأقران، مع التحكم بالميكروفون والكاميرا.
- واجهة عربية RTL.

## التشغيل على الشبكة

1. شغّل التطبيق على أجهزة Windows في الشبكة المحلية نفسها؛ لا تختَر جهازًا مضيفًا.
2. اسمح بالتطبيق عبر جدار حماية Windows ضمن **الشبكات الخاصة** على كل جهاز. المنفذ TCP `43821` للاتصالات المباشرة وUDP `43820` للاكتشاف، إضافة إلى حركة UDP الخاصة بـWebRTC.
3. تظهر الأجهزة بعد اكتشافها تلقائيًا. يجب السماح بحركة المرور المباشرة بين عملاء الشبكة وتعطيل عزل Wi‑Fi؛ الشبكات الفرعية المختلفة قد تمنع UDP broadcast.
4. الرسائل الخاصة المؤجلة تعتمد على بقاء جهاز المرسل متاحًا حتى يتصل المستلم به. لا يوجد صندوق بريد سحابي أو جهاز مركزي دائم.

## حدود التوافق الحالية

- **Windows:** تطبيق Electron هو العميل المنفذ حاليًا.
- **Android:** لا يوجد APK أو عميل Android في هذه النسخة؛ التوافق يحتاج تنفيذًا واختبارًا مستقلين.
- **Bluetooth:** غير مدعوم؛ النقل الحالي يستخدم IP عبر Wi‑Fi/Ethernet، لا Bluetooth.
- **اتصال عبر الإنترنت/VPN أو شبكات فرعية:** لم يُختبر أو يُدعَم عبر NAT؛ التصميم الحالي موجه للشبكة المحلية القابلة للوصول المباشر.

## الخصوصية والأمان

لا يتطلب التطبيق خدمة سحابية أو اتصالًا بالإنترنت. تحفظ الرسائل والملفات محليًا على الأجهزة المشاركة. **تنبيه:** اتصالات Socket.IO/HTTP المحلية غير مشفرة ولا توجد مصادقة تشفيرية موثوقة لهوية الأجهزة. استخدمه على شبكة موثوقة فقط، ولا تتبادل معلومات حساسة قبل إضافة TLS/تشفير طرفي ومصادقة أقران ومراجعة أمنية. نسخة Windows غير موقعة رقميًا وقد يعرض SmartScreen تحذيرًا.

## التطوير والاختبار

يتطلب Node.js 20 أو أحدث.

```bash
npm ci
npm start
npm test
```

## بناء Windows

```bash
npm ci
npm test
npm run build:win
```

ينشئ Electron Builder مثبت NSIS ونسخة portable بصيغة EXE في `release/`. كما يمكن تشغيل سير عمل **Build Windows installer** في GitHub Actions وتنزيل artifact باسم `fursan-lan-windows-installers`.

## ما تم التحقق منه وما يحتاج اختبارًا عمليًا

تشغّل `npm test` اختبارات التخزين والترحيل والخصوصية وطابور الرسائل واستئناف رفع المقاطع والملفات والمجموعات. ينبغي اختبار نسختين أو أكثر فعليًا على Windows للتأكد من الاكتشاف عبر جدار الحماية، وإرسال رسائل وملفات مباشرة دون إعادة تمريرها، وإيصالات القراءة، وجودة WebRTC قبل الاعتماد المؤسسي.
