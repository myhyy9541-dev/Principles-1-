# بنية واصل Java — الإصدار 0.5.1

## القرار التقني

- التطبيق المكتبي، خادم الغرفة، اكتشاف الشبكة، التخزين الدائم، إدارة الملفات، الإعدادات، ومشغّل Windows كلها Java 21.
- واجهة RTL الحالية HTML/CSS/JavaScript تعمل داخل Chromium مضمّن بواسطة JCEF؛ لذلك لا يحتاج التطبيق Node.js أو تثبيت Java منفصلاً عند المستخدم بعد إنشاء الحزمة. واجهة JavaScript هنا طبقة عرض فقط، وليست خادم التطبيق.
- Socket.IO Java (`netty-socketio`) يتيح بقاء أحداث الواجهة متوافقة مع Socket.IO 4. النقل WebRTC مباشر بين الأجهزة داخل الشبكة، من دون STUN/TURN سحابي.
- يضم التطبيق `slf4j-simple` 2.0.16 كموفّر لـ`slf4j-api` ويضبط `simplelogger.properties` المستوى الافتراضي على WARN؛ تُسجل التحذيرات والأخطاء دون تحذير غياب موفّر التسجيل.
- ملف عميل Socket.IO مضمن محلياً في الحزمة، ولا توجد CDN أو خطوط خارجية.

## الشبكة والمنافذ

| الاستخدام | المنفذ | الربط |
|---|---:|---|
| واجهة التطبيق وAPI الإعدادات | TCP 43819 | loopback `127.0.0.1` فقط |
| اكتشاف الغرفة وإعلانها | UDP 43820 | بطاقة الشبكة المختارة |
| Socket.IO للدردشة والإشارات | TCP 43821 | واجهات الشبكة المحلية |
| تنزيل الملفات ومعاينة الصور | TCP 43822 | واجهات الشبكة المحلية |
| Socket.IO لوضع P2P | TCP 43823 | واجهات الشبكة المحلية |
| اكتشاف الأجهزة P2P | UDP 43820 | بطاقة الشبكة المختارة |
| الصوت/الفيديو | WebRTC/ICE | منافذ UDP يختارها Windows تلقائياً |

اكتشاف UDP لا يعبر عادةً VLAN أو شبكات فرعية مختلفة؛ يمكن استخدام عنوان IP اليدوي عند السماح بالاتصال عبر الراوتر. يجب أن تكون الأجهزة على شبكة موثوقة واحدة، مع تعطيل عزل العملاء في نقطة Wi-Fi عند الحاجة. إذا ظهر تنبيه Windows Firewall لأول مرة، اسمح للتطبيق على **Private networks** فقط، ولا تفعّله على الشبكات العامة.

يستخدم اكتشاف Java بروتوكول `wasel-lan-java-v1` للمضيف، وبروتوكول `wasel-lan-p2p-v1` للأجهزة التي تعمل في الوضع المباشر. كل جهاز يشغل خدمة P2P محلية، ويكتشف الأجهزة المعلنة ثم يتصل بخوادمها مباشرة. لا يوجد خادم مركزي ولا حاجة إلى اتصال إنترنت. يظل وضع المضيف المؤقت على المنفذ 43821 خياراً منفصلاً. لتعمل الميزات كما صُممت، حدّث أجهزة المنشأة جميعها إلى إصدار Java 0.5.1 أو أحدث.

في P2P تكون المحادثة العامة والرسائل الخاصة متاحة عبر اتصالات الأجهزة المباشرة، وتنقل الملفات إلى خدمة الملفات على الجهاز الذي يستضيفها. المكالمة تبدأ مع المستخدم المحدد فقط، وتنتقل الإشارات إلى ذلك الطرف. الصوت والفيديو يستخدمان WebRTC بين الأجهزة. المجموعات والبث المخزن في سجل مركزي ما زالا ضمن وضع المضيف المؤقت، وليسا ضمن نطاق P2P الحالي.

## إعدادات المستخدم والبيانات

- شاشة الإعدادات: الاسم الظاهر، بطاقة IPv4/عنوانها وقناعها وMAC، تردد البث (0.5–15 ثانية)، الاتصال التلقائي، الاتصال اليدوي، المظهر، والتشغيل عند تسجيل الدخول.
- معرف العميل والاسم محفوظان في ملف Chromium المحلي الدائم على المنفذ المحلي الثابت، كي تبقى هوية الجهاز ثابتة بعد إغلاق التطبيق.
- على Windows تحفظ الملفات في `%APPDATA%\\wasel-lan`: `settings.json`، وسجل `wasel-room`، وملفات المشاركة، وملف تعريف المتصفح. تُجرى محاولة نسخ آمنة لسجل Electron السابق من مجلدات `wasel-lan` المعتادة إذا لم يوجد سجل Java.
- وضع المضيف مؤقت كما طلب المستخدم: يعمل حتى إغلاق برنامج المضيف، ولا يوجد خادم دائم/سحابي. وضع P2P يشغل خدمة على كل جهاز ويوقفها عند اختيار المضيف أو إغلاق التطبيق.
- حد الملف 1 GiB، وسقف تخزين الملفات على كل جهاز مستضيف 10 GiB، والرسائل النصية حتى 5000 حرف. تُرفع الملفات في مقاطع 1 MiB لتقليل عدد جولات التأكيد، ويُثبّت الملف على القرص عند اكتماله بدلاً من إجبار القرص على المزامنة بعد كل مقطع. سرعة النقل الفعلية تظل مرتبطة بسرعة بطاقات الشبكة والقرص ومعالجة الجهاز.

## الصوت والكاميرا

لا تعرض واجهة JCEF Java API موحدة لـpermission handler في النسخة المستخدمة. لتمكين WebRTC الفعلي على Windows يمرر مشغّل Chromium المضمن خيارات media stream اللازمة، ويُطلب الوصول من واجهة الاتصال بعد ضغط المستخدم على زر الصوت/الفيديو أو موافقته على مكالمة واردة. يستطيع المستخدم كذلك منع الوصول من إعدادات خصوصية الكاميرا والميكروفون في Windows. يجب اختبار أجهزة الكاميرا والميكروفون الفعلية في نسخة Windows قبل نشرها على نطاق المنشأة؛ اختبار Sandbox لا يملك عتاد Windows.

## البناء والتحقق

- Windows x64، Windows 10 وما بعده: JDK 21 وMaven وWiX في GitHub Actions.
- `jpackage` ينشئ مثبت EXE لكل مستخدم، ويضم Runtime Java؛ ويصدر سير العمل أيضاً نسخة portable.
- التطبيق الأصلي لـJCEF وChromium كبير الحجم؛ لذلك حزمة التطبيق أضخم من نسخة Electron. يضم التثبيت المكتبات الأصلية كي لا يحتاج اتصالاً بالإنترنت بعد التنزيل.
- اختبارات Java: `mvn clean test`; البناء: `mvn package`.
- اختبارات التكامل المحلية: Socket.IO 4 مع عميلين، الرسائل الخاصة، قائمة الأعضاء، إعادة تسليم الرسائل بعد عودة المستلم، المجموعات/إيصالات القراءة، ورفع ملف ثم تنزيل بايتاته من خادم الملفات.
- لا يثبت اختبار Sandbox وحده توافق الأجهزة/برامج التشغيل على Windows؛ يظل اختبار الكاميرا والميكروفون وسياسة جدار الحماية على Windows حقيقياً قبل الإطلاق النهائي.
